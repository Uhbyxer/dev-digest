# Development Plan: Export to CI

## Context
Implements SPEC-2026-07-08-export-to-ci (`docs/specs/export-to-ci.md`). The agent-runner (`agent-runner/`, `dist/index.js`, see `AGENT-RUNNER.md`) already exists. Missing: the server `ci/` module and routes, YAML/workflow generation, GitHub adapter capabilities (atomic commit + PR, workflow runs + artifacts), the Export Wizard, the agent CI tab, and the global CI Runs page. Contracts live in `server/src/vendor/shared/contracts/eval-ci.ts` and the client copy; every shared change is made in BOTH copies. UI reference is the spec text (AC-1..4, 7, 8, 10, 33, 34); screenshots are not in the repo. Spec ACs are referenced, not restated. v1 = simplest correct form (spec "simplicity first"); security ACs (15-19, 21, 27) are non-negotiable.

## Execution mode
Multi-agent: implementer -> test-writer -> plan-verifier -> architecture-reviewer -> doc-writer, split by module and by stage. Stage A: steps 1-7 (server, shared, client). Stage B: steps 8-11. Implementer does the steps per module; test-writer owns `*.it.test.ts` and e2e.

## Decisions from clarification
- Runner bytes: server reads `agent-runner/dist/index.js` from disk via a `RunnerBundleProvider` port; the committed dist is the artifact; a test asserts exported bytes equal the file.
- `ci_runs` table is left untouched (not the runs store). Migration only adds columns.
- Idempotent ingest: natural unique index plus `ON CONFLICT DO NOTHING`.
- Ingest is synchronous on `POST /ci/refresh`; GETs are read-only; no poller.
- Slug derived from name, deterministic `-2`, `-3` suffixes, ordered by `createdAt`; no slug column.
- agent-runner: only verify AC-19..26 against existing tests; add tests if gaps; do not rebuild dist unless code changes.
- "Update CI config" = same wizard pre-filled; no separate endpoint.
- Navigation: sidebar item "CI Runs" at `/ci-runs`; CI tab in `agents/[id]`.
- R1 accepted: two stages (A: backend + wizard + CI tab; B: CI Runs + ingest). R2 accepted: workflow generated by a template string in one file.

## Architectural constraints
- `reviewer-core` untouched; no new deps there. Ports in `server/src/vendor/shared/adapters.ts` (`GitHubClient`), adapters in `server/src/adapters/` (onion-architecture skill).
- Schema change needs explicit `pnpm db:migrate`; server does not migrate on boot.
- Never read/write `server/clones/**`.
- Review `server/INSIGHTS.md` and `client/INSIGHTS.md` before starting; `agent-runner/insights/INSIGHTS.md` if step 6 touches it.
- Export makes NO GitHub Secrets API call (AC-9). No inbound ingest route (AC-27).
- `agent-runner` reading `process.env` is intentional (its CLAUDE.md); do not "fix" it.

## ADR conflicts
None.

## Steps

### Stage A

### 1. Shared contracts + DB migration — module: server (+ client vendor copy)
- Files: `server/src/vendor/shared/contracts/eval-ci.ts` and `client/src/vendor/shared/contracts/eval-ci.ts`; `server/src/db/schema/ci.ts`; `server/src/db/schema/runs.ts`; new migration in `server/src/db/migrations/` (generate via drizzle-kit).
- Skill(s): drizzle-orm-patterns, postgresql-table-design, zod, typescript-expert
- What: add `status` and `workflow_version` to `CiInstallation` and `ci_installations`; unique `(agent_id, repo, target_type)` for upsert. Add to `agent_runs` nullable CI metadata: `ci_installation_id` (FK, set null), `ci_pr_number`, `ci_repo`, `ci_job_url`, `ci_github_run_id`, with a partial unique index on `(ci_installation_id, ci_github_run_id, ci_pr_number)` where `source='ci'`. Add a `CiRunRow`/list DTO for the CI Runs page. Keep `ci_runs` untouched. Run `pnpm db:migrate` locally. (AC-12, AC-28, AC-30)

### 2. Slug + manifest + workflow generation — module: server
- Files: `server/src/modules/ci/slug.ts`, `manifest.ts`, `workflow.ts` (template string, pure).
- Skill(s): typescript-expert, zod
- What: `slugify` + deterministic disambiguation (AC-6, stable across re-exports); `buildManifest(agent, skills)` emitting YAML (add `yaml` dep to `server/package.json`) validated with `AgentManifest.safeParse` (AC-5, AC-36); `buildWorkflow({triggers, postAs})` producing `.github/workflows/devdigest-review.yml`: `on: pull_request` only with chosen types (AC-7, AC-18), `permissions` exactly `contents: read` + `pull-requests: write` (AC-15), key only via `secrets.OPENROUTER_API_KEY` (AC-16), job `if: github.event.pull_request.head.repo.full_name == github.repository` so forks never get the keyed job (AC-17), step `node .devdigest/runner/index.js` with `DEVDIGEST_POST_AS`, uploads `devdigest-result.json` artifact, no marketplace `uses:` for review (AC-19). Unit tests assert each security property.

### 3. Runner bundle provider + file assembly — module: server
- Files: `server/src/adapters/runner-bundle/` (fs reader), port in `server/src/vendor/shared/adapters.ts`, `server/src/modules/ci/files.ts`, `server/src/platform/container.ts`, `server/src/adapters/mocks.ts`.
- Skill(s): typescript-expert
- What: assemble 6-file set: manifest, skill files `.devdigest/skills/<slug>.md`, empty `.devdigest/memory.jsonl`, read-only `.devdigest/runner/index.js`, editable workflow (AC-3, AC-4, Q10). Non-GHA targets produce a config file for download only (Q3).

### 4. GitHub adapter: atomic commit + PR — module: server
- Files: `server/src/vendor/shared/adapters.ts` (`GitHubClient`), `server/src/adapters/github/octokit.ts`, `server/src/adapters/mocks.ts`.
- Skill(s): typescript-expert
- What: add `commitFilesToBranch({repo, base, branch:'devdigest/ci', files, message})` (git data API: blobs, tree, one commit, create or force-update ref; never touches base) and `openOrUpdatePr` (find open PR from `devdigest/ci`, else create "Add DevDigest CI review"). (AC-10, AC-11)

### 5. CI service, repository, routes (export, installations, fail-on) — module: server
- Files: `server/src/modules/ci/{repository,service,routes}.ts`, `server/src/modules/index.ts`.
- Skill(s): fastify-best-practices, drizzle-orm-patterns, zod
- What: `POST /agents/:id/ci/export` (`CiExportInput`; `action: files` returns zip data/ files with no PR or installation (AC-13); `open_pr` commits, opens PR, upserts installation with `status`/`workflow_version` only after GitHub success (AC-12, AC-14)); `GET /agents/:id/ci/installations`; local OpenRouter key readiness exposed from SecretsProvider only (AC-8, AC-9). Fail-CI-on persists through the existing agent update path (AC-35), accepting `critical|warning|never` from the UI.

### 6. Verify agent-runner against AC-19..26 — module: server (package `agent-runner/`)
- Files: `agent-runner/src/**` tests only unless a gap is found.
- Skill(s): typescript-expert
- What: check existing tests cover AC-20..26 and the 6-file path; add tests for gaps. Rebuild dist (`pnpm build` in agent-runner) only if source changes.

### 7. Client: CI tab + Export Wizard — module: client
- Files: `client/src/app/agents/[id]/_components/CiTab/*`, `client/src/app/agents/[id]/_components/ExportWizard/*` (steps Target/Preview/Configure/Install), API hooks in `client/src/lib/`, i18n strings in `client/src/i18n`.
- Skill(s): react-nextjs-architecture, next-best-practices, react-best-practices, typescript-expert
- What: header "CI deployment", "Active in N repos" badge, Update CI config / Add to CI buttons, Fail CI on selector (Critical / Warning + / Never), installation rows (target badge, workflow version), "Add repository" opening the wizard (AC-34, AC-35). Wizard on the existing `Modal` primitive (dialog semantics): AC-1, AC-2, AC-3 (only workflow editable; edits sent to install; runner shown as placeholder with size), AC-7, AC-8 (secrets rows + branch-protection hint), AC-10 (PR title, repo, file count), AC-13 zip fallback, AC-14 error display. Update CI config reuses the wizard prefilled.

No inbound ingest route (AC-27).
